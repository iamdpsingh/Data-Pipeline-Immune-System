# ADR-004: Medallion Architecture, Dead-Letter Quarantine, and BigQuery Storage Design

- **Status**: Accepted
- **Deciders**: Architecture Team, Data Platform Lead, Analytics Engineering
- **Date**: 2026-10
- **Technical Context**: Lakehouse Data Modeling, Partitioning, and Telemetry Storage

---

## 1. Context and Problem Statement

The **Data Pipeline Immune System** requires a data architecture capable of supporting two distinct workloads:
1. **Production Business Pipelines**: Ingesting, transforming, and serving high-throughput retail transactions across bronze, silver, and gold tiers.
2. **Autonomous Observability & Incident Telemetry**: Storing high-frequency data quality metrics, pipeline health scores, agent diagnostic reasoning trails, and remediation logs with zero data-loss guarantees and sub-second SQL retrieval.

Key challenges include:
- How to isolate corrupt or malformed records without failing entire multi-gigabyte ingestion batches.
- How to structure BigQuery tables for cost-effective time-series scanning across millions of health checks.
- How to preserve auditability for every autonomous decision taken by the immune agents.

---

## 2. Decision Outcome

We adopted a **Medallion Lakehouse Pattern** coupled with a **Dead-Letter Quarantine Subsystem** and a dedicated **BigQuery Audit & Telemetry Store**:

```
[External Sources]
       |
       v (Raw Ingestion)
+--------------------------------------------------------------+
| Bronze Tier: GCS gs://dpis-{env}-source & BigQuery Raw      |
| Append-only, preserves source schema, includes _ingested_at  |
+------------------------------+-------------------------------+
                               |
                               v (PySpark Validation & Conformance)
+--------------------------------------------------------------+
| Validation & Quarantine Gate (src/validation/quality_engine) |
+--------------+-------------------------------+---------------+
               |                               |
       [Valid Records]                 [Invalid Records]
               |                               |
               v                               v
+-----------------------------+ +------------------------------+
| Silver Tier (Conformed)     | | Quarantine Tier              |
| BigQuery dpis_silver        | | GCS: gs://dpis-{env}-quarantine
| Partitioned by date         | | BQ: dpis_audit.quarantine_records
| Clustered by customer_id    | | Preserves payload & reason   |
+--------------+--------------+ +------------------------------+
               |
               v (Aggregation)
+-----------------------------+
| Gold Tier (Aggregates)      |
| BigQuery dpis_gold          |
| Reporting & KPI tables      |
+-----------------------------+
```

## 3. Storage Layer Specifications

### 3.1. Lakehouse Medallion Tiers

| Tier | Dataset / Bucket | Storage Type | Schema Contract & SLA | Partitioning / Clustering |
|---|---|---|---|---|
| **Raw / Source** | `gs://dpis-{env}-source/orders/` | GCS Objects (JSON/CSV) | Immutable landing; retention 90 days | Path-based: `/year/month/day/` |
| **Bronze** | `data-pipeline-immune-system.dpis_bronze.orders_raw` | BigQuery Table | Raw payload + `_ingested_at`, `_source_file` | Partitioned by `DATE(_ingested_at)` |
| **Silver** | `data-pipeline-immune-system.dpis_silver.orders` | BigQuery Table | Strongly typed relational contract; deduped | Partitioned by `DATE(order_date)`, Clustered by `(customer_id, status)` |
| **Gold** | `data-pipeline-immune-system.dpis_gold.daily_order_summary` | BigQuery Table | Pre-aggregated business dimensions | Partitioned by `DATE(summary_date)`, Clustered by `(region)` |

### 3.2. Dead-Letter Quarantine Subsystem (ADR-008 Implementation)

When records fail quality constraints (e.g., negative prices, unparseable dates, null primary keys, unmapped foreign references), failing the entire batch introduces severe operational delays. 

Instead, the [QuarantineHandler](file:///Volumes/Work/daemons-lab/d.automation/Data%20Pipeline%20Immune%20System/spark/utils/quarantine.py) segregates valid from invalid rows:
- **Valid Rows**: Written downstream to `dpis_silver.orders` without delay.
- **Corrupted Rows**: Written to `dpis_audit.quarantine_records` with structural metadata:
  - `quarantine_id`: UUID primary key.
  - `pipeline_id`: Source pipeline identifier (e.g. `orders_ingestion`).
  - `raw_record`: Native JSON string of the rejected row.
  - `rejection_rule`: Specific rule violated (e.g. `RULE_ORDER_AMOUNT_POSITIVE`).
  - `severity`: Error severity (`WARNING` vs `CRITICAL`).
  - `status`: Lifecycle state (`QUARANTINED`, `REPROCESSED`, `PURGED`).

### 3.3. Immune Observability & Audit Schema (`dpis_audit`)

All telemetry generated by the immune system is persisted in dedicated partitioned tables:

1. **`dpis_audit.data_quality_results`**:
   - Records every check execution (row counts, null fractions, freshness, distribution z-scores).
   - Partitioned by `check_timestamp`; clustered by `(pipeline_id, check_type, status)`.
2. **`dpis_audit.pipeline_health_scores`**:
   - Rolling composite health score (0–100) combining freshness, volume, quality, and SLA adherence.
   - Partitioned by `recorded_date`.
3. **`dpis_audit.incident_events`**:
   - Lifecycle state machine records: `DETECTED` -> `DIAGNOSED` -> `RISK_ASSESSED` -> `REMEDIATED` -> `VERIFIED` -> `RESOLVED`.
   - Partitioned by `created_at`; clustered by `(incident_id, severity, status)`.
4. **`dpis_audit.remediation_audit`**:
   - Immutable record of every automated action attempted or executed.
   - Includes action parameters, target pipeline, execution output, and idempotency tokens.
5. **`dpis_audit.incident_memory`**:
   - Diagnostic knowledge base storing resolved incident symptoms, root causes, effective remediations, and text embeddings for similarity retrieval.

## 4. Consequences and Trade-offs

### Positive:
- **Data Integrity Guarantee**: Zero corrupt records enter `dpis_silver` or `dpis_gold`.
- **Query Efficiency**: Partitioning and clustering reduce BigQuery data scan costs by >85% for agent health checks and daily SLA monitoring.
- **Regulatory Compliance**: Complete, tamper-evident audit trail of all automated remediation actions and quarantined payloads.

### Trade-offs:
- **Downstream Discrepancies**: If 1% of rows are quarantined, downstream gold aggregates reflect a temporary delta until quarantined rows are remediated and reprocessed.
- **Storage Redundancy**: Retaining raw payloads in both GCS and BigQuery bronze increases total raw storage footprint by ~20%, mitigated by standard GCS lifecycle policies.
